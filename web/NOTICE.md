# Third-party notices for the web bundle

The editor in this bundle is [helix](https://github.com/helix-editor/helix)
plus the browser port at <https://github.com/Jecoms/helix-wasm>, both under
the Mozilla Public License 2.0. Its text ships beside this file — `LICENSE` in
the release tarball, `LICENSE.txt` at the root of the deployed demo — and is
that repository's top-level `LICENSE`
(<https://github.com/Jecoms/helix-wasm/blob/main/LICENSE>); the repository is
also where the corresponding source form lives. What follows covers the
third-party code and content the bundle carries under other terms: the Rust
crates it is compiled from, the tree-sitter grammars and runtime it statically
links, and the helix runtime files it embeds.

The wasm is a Rust binary, and most of what it is compiled from is not the
editor's own code: the crates it links reach it through cargo, under their own
MIT, Apache-2.0 and other terms. Every one of them is enumerated in
"[Rust crates](#rust-crates)" below, generated from the dependency graph of the
build that produces this artifact.

The distributed wasm artifact statically links the C parser sources of the
tree-sitter grammars below (the `GRAMMARS` catalog in `build.rs`, fetched at
build time at the pinned revisions). All of them are MIT-licensed; the
copyright lines are reproduced verbatim from each repository's `LICENSE`
file at the pin, and the MIT license text follows at the end.

It also statically links the tree-sitter runtime those parsers run under: the
core C library plus the small subset of ICU headers that C includes, both
vendored in this repository under `stubs/tree-house-bindings/vendor/` and
compiled by that crate's `build.rs`. Their notices are in
"[tree-sitter runtime](#tree-sitter-runtime)" below.

It further embeds three kinds of runtime files from the in-tree helix port at
`../helix/runtime/`, read where they lie rather than copied into this crate:

- the tree-sitter query files under `helix/runtime/queries/`, for the
  languages the grammar catalog selects — see `queries/README.md`;
- the theme files under `helix/runtime/themes/`, for the curated set in
  `build.rs`'s `THEME_CATALOG` — see `themes/README.md`;
- the tutor text at `helix/runtime/tutor` — see `runtime/README.md`.

Those are helix's own files and MPL-2.0 like the rest of the editor (the
repository's top-level `LICENSE`, linked above) — with one exception: upstream
carries per-theme licenses in `helix/runtime/themes/licenses/` for themes
contributed under other terms, and one of the embedded themes has an entry
there. It is in "[Themes](#themes)" below.

When bumping a grammar pin, re-check its `LICENSE` and update the matching
entry here. When adding a theme to `THEME_CATALOG`, check
`helix/runtime/themes/licenses/` for a file matching its name and add a row
below if there is one. The same applies when re-vendoring
`stubs/tree-house-bindings` (its `Cargo.toml` header carries the refresh
recipe): re-check `vendor/LICENSE` and `vendor/src/unicode/LICENSE` against
the section below. The crate table needs no such discipline — it is generated,
and CI fails if it drifts from `Cargo.lock` (see below).

## Rust crates

Every crate whose compiled code is in the wasm, with the license its own
manifest declares and the copyright lines its own license files carry. The
table is generated by `web/notice-crates.py` from the dependency graph of
`helix-web` resolved for `wasm32-unknown-unknown` — the same graph
`wasm-pack build web` compiles — and the `wasm32 check` workflow re-runs the
generator with `--check` on every pull request, so it cannot silently fall
behind `Cargo.lock`. To refresh it after a dependency change:

```sh
cargo fetch --locked
python3 web/notice-crates.py
```

What the table is and is not:

- **Only what ships.** Normal dependencies for the wasm target. Dev
  dependencies never reach a release build, and build dependencies and
  proc-macros run on the build host — no byte of them is in the artifact — so
  they are not listed. (`cc` and `unicode-ident` do appear: something also
  depends on each of them as an ordinary dependency.)
- **No election.** Where a crate offers a choice — `MIT OR Apache-2.0` is the
  common case — the whole expression is reproduced rather than one branch of
  it. Choosing is the recipient's to do, and the text of every license named
  below is either reproduced at the end of this file or, for `MPL-2.0`, the
  `LICENSE` that ships beside it.
- **Verbatim copyright.** The copyright column is copied out of the crate's
  own license files, from the published `.crate` archive at the listed
  version. A `—` means the crate ships no copyright line — a fact about the
  crate, not a hole in this notice.
- **Path entries.** A `Source` that is a repository path is code in this
  repository rather than a registry download: the in-tree helix port under
  `helix/`, the wasm32 substitutions under `stubs/`, and the port's own two
  crates. Four of the stubs are vendored third-party code and declare their
  upstream license; `stubs/home`, `stubs/libloading` and `stubs/which` are
  from-scratch API-compatible shims written for this port, containing no
  upstream code, and are marked `MPL-2.0 (repository)` — their manifests
  declare no license and the repository's `LICENSE` governs.

One row is worth calling out because it is easy to assume otherwise:
`helix-lsp-types` sits inside the `helix/` tree but is **MIT**, not MPL-2.0 —
it is upstream helix's fork of `lsp-types`, and it keeps that crate's license
(`helix/helix-lsp-types/LICENSE`).
